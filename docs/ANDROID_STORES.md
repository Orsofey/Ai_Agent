# Android: сборка APK и AAB для Google Play и RuStore

Приложение «Андрей» для Android — пульт агента на ПК: команды голосом или текстом,
ответы озвучиваются на телефоне. Телефон и компьютер должны быть в одной сети Wi‑Fi.
Подключение — QR-код на ПК: Настройки → «iPhone и Android».

## 1. Что установить на ПК с Windows (один раз)

1. **Flutter stable** — https://docs.flutter.dev/get-started/install/windows.
   Папку `flutter\bin` добавьте в PATH.
2. **Android Studio** — https://developer.android.com/studio.
   При первом запуске Android Studio установит Android SDK и JDK.
3. В новом окне командной строки выполните `flutter doctor --android-licenses`
   и примите лицензии: на все вопросы ответьте `y`.
4. Проверьте установку: `flutter doctor`. Строки Flutter и Android toolchain должны быть с галочкой.

## 2. Сборка

```
BUILD_ANDROID.bat          :: APK и AAB
BUILD_ANDROID.bat aab      :: только AAB (Google Play, RuStore)
BUILD_ANDROID.bat apk      :: только APK (RuStore, установка вручную)
```

Готовые файлы появятся в папке `release\`:

- `LocalAIAgent.aab` — для Google Play и RuStore;
- `LocalAIAgent.apk` — для RuStore или установки на телефон напрямую.

Версия берётся из `app.py` (например, 5.4.0). Номер сборки растёт автоматически при каждой
сборке — магазины не принимают файл с тем же или меньшим номером. Задать номер вручную можно
переменной окружения `LOCAL_AI_ANDROID_BUILD_NUMBER`.

## 3. Ключ подписи — сохраните его!

При первой сборке создаётся ключ в папке `%LOCALAPPDATA%\LocalAIAgent\signing\`:
файлы `android-release.jks` и `android-signing.json` (в нём пароль).

- **Сделайте резервную копию этой папки** (флешка или зашифрованный архив).
  Без ключа нельзя выпускать обновления в RuStore и для тех, кто поставил APK.
- Никому не пересылайте эти файлы и не кладите их в репозиторий.

Идентификатор приложения — `com.localaiagent.local_ai_agent`. После первой публикации
его изменить нельзя.

## 4. Google Play (Play Console)

1. Зарегистрируйтесь в https://play.google.com/console.
   Разовый взнос для аккаунта разработчика — 25 $.
2. Нажмите «Создать приложение»: название «Андрей», тип «Приложение», «Бесплатное».
3. Выберите «Тестирование → Внутреннее тестирование → Создать выпуск».
   Включите **Подписание приложений в Google Play** — это рекомендуемый вариант.
   Ваш ключ из пункта 3 станет *ключом загрузки*.
4. Загрузите `release\LocalAIAgent.aab`.
5. Заполните «Контент приложения»:
   - **Политика конфиденциальности** — нужна ссылка на страницу. Например, разместите
     текст на своём сервере Amvera.
   - **Безопасность данных.** Звук с микрофона передаётся только на ваш компьютер
     в локальной сети и не отправляется разработчику. Данные не собираются и не передаются третьим лицам.
   - **Разрешения**: микрофон нужен для голосовых команд, камера — для сканирования QR-кода подключения.
6. Новым личным аккаунтам Google требует закрытое тестирование: не меньше 12 тестировщиков
   в течение 14 дней. Только после этого можно выпускать приложение в продакшн.

## 5. RuStore (RuStore Консоль)

1. Зарегистрируйтесь в https://console.rustore.ru. Для физлица и самозанятого это бесплатно.
2. Нажмите «Создать приложение». Имя пакета — `com.localaiagent.local_ai_agent`.
3. Загрузите **APK** (`release\LocalAIAgent.apk`) — это самый простой путь.
   Если загружаете **AAB**, RuStore попросит ключ подписи, чтобы собирать из него APK.
   Следуйте подсказке консоли и выгрузите ключ из `android-release.jks`.
4. Заполните карточку: описание, скриншоты, возрастной рейтинг, ссылку на политику конфиденциальности.
5. Отправьте приложение на модерацию. Обычно она занимает 1–3 рабочих дня.

## Частые ошибки

- **`[WinError 193] %1 is not a valid Win32 application`.** Исправлено в скрипте: теперь
  он запускает `flutter.bat`. Обновите репозиторий (`git pull`).
- **`Not found: flutter`.** Flutter не добавлен в PATH. Откройте новое окно командной строки
  после установки.
- **`No Android SDK found`.** Установите Android Studio и откройте её один раз.
  Затем выполните `flutter doctor --android-licenses`.
- **`Signing keystore is missing`.** Восстановите папку `signing` из резервной копии.
  Новый ключ не создавайте, если приложение уже опубликовано.
