# Интеграции: как «Андрей» читает данные других приложений и действует в них

Настройки → **Управление ПК** → «Интеграции с приложениями» → **Папка интеграций…**
(`%LOCALAPPDATA%\LocalAIAgent\integrations`). Каждый файл в папке — одна интеграция; новые файлы
подхватываются без перезапуска. Пример `example.json.txt` появляется при первом открытии.

## Три способа связаться с приложением

| Способ | Когда подходит | Пример |
|---|---|---|
| **HTTP API приложения** | у приложения есть API или вебхуки (Notion, Todoist, YouGile, Трекер Яндекса, Google Sheets, свой сервер) | «Что в трекере на сегодня?» → GET к API → ответ голосом |
| **Файл экспорта** | приложение умеет выгружать JSON/CSV (многие трекеры, банки, фитнес) | нейросеть отвечает по данным файла |
| **Управление окном** | API нет вообще | команды «напиши…», «нажми Ctrl+…», макросы, как для Telegram и Discord |

## JSON-интеграция — без программирования

```json
{
  "name": "Трекер",
  "commands": [
    {"phrases": ["что в трекере( на (?P<day>сегодня|завтра))?", "мои задачи"],
     "method": "GET", "url": "https://tracker.example/api/tasks?day={day}",
     "headers": {"Authorization": "Bearer {secret:TRACKER_TOKEN}"},
     "say": "Задач: {count}. {items[*].title}"},
    {"phrases": ["добавь в трекер (?P<text>.+)"],
     "method": "POST", "url": "https://tracker.example/api/tasks", "json": {"title": "{text}"},
     "say": "Добавил в трекер: {text}"}
  ],
  "context": {"phrases": ["трекер", "задач", "привычк"], "file": "~/Documents/tracker-export.json"}
}
```

- `phrases` — что говорить (регулярные выражения; `(?P<имя>…)` — часть фразы, которая подставится в `{имя}`).
- `url` + `method` (GET/POST/PUT/PATCH/DELETE), `headers`, `json` — запрос к API приложения. Только http(s).
- `file` вместо `url` — локальный JSON, CSV или TXT.
- `say` — ответ голосом: `{поле}`, `{поле.вложенное}`, `{список[*].поле}`, `{count}`.
- `context` — если вопрос содержит эти слова, данные передаются нейросети вместе с вопросом:
  «Как у меня с привычками на этой неделе?» — локальная нейросеть ответит по вашим данным.
- Токены и пароли — не в файле интеграции: `{secret:ИМЯ}` берётся из `integrations/secrets.json`
  (`{"TRACKER_TOKEN": "…"}`) или из переменной окружения.

## Python-плагин — для сложной логики

`integrations/steps.py`:

```python
NAME = 'Шаги'

def steps(match, settings):
    # здесь можно читать файл, базу, вызывать API с подписью, считать статистику…
    return 'Сегодня 8 000 шагов.'

COMMANDS = [(r'сколько шагов( сегодня)?', steps)]

def context(question, settings):          # необязательно: данные для вопросов нейросети
    return 'Шаги за неделю: 8000, 6500, 12000' if 'шаг' in question else None
```

Плагин выполняется с правами самого ассистента — ставьте только свои или проверенные файлы.

## Трекер «из диалогов со мной»

Если ваш Tracker — это приложение (артефакт), которое мы делали в чате на claude.ai, его данные хранятся
на стороне claude.ai, и программа на ПК не может читать их напрямую: у артефактов нет открытого API для
внешних программ. Рабочие варианты:

1. **Экспорт.** Добавить в Tracker кнопку «Скачать данные (JSON)» → сохранить файл, например,
   в `Документы\tracker-export.json` → указать его в `context.file` интеграции. «Андрей» будет отвечать
   по вашим данным; обновлять — повторным экспортом.
2. **Свой сервер Трекера.** Перенести хранение данных Трекера на сервер с API (его можно разместить рядом
   с сервером аккаунтов на Amvera) — тогда «Андрей» читает и добавляет записи голосом в реальном времени
   через JSON-интеграцию с `url`.

Пришлите ссылку на Tracker или его формат данных — подготовлю готовый файл интеграции.

## Стандарт на будущее: MCP

Многие сервисы сейчас выпускают MCP-серверы (Model Context Protocol) — единый способ дать ИИ-ассистенту
данные и действия приложения. Интеграции «Андрея» устроены так же (команды + данные для контекста), поэтому
MCP-сервер конкретного приложения можно обернуть Python-плагином.
